# ГОРИЗОНТ — розгортання на Railway

Інструкція для публікації карти на https://railway.com/.
Автор проєкту: Viacheslav Tykhenkyi.

---

## Що вже підготовано

Ці файли лежать у папці проєкту й потрібні саме для хостингу:

| Файл | Навіщо |
|---|---|
| `Procfile` | команда запуску: `web: python server.py` |
| `requirements.txt` | порожній (залежностей немає), але без нього Railway може не розпізнати проєкт як Python |
| `runtime.txt` | версія Python (3.12) |
| `.gitignore` | щоб у репозиторій не потрапили `__pycache__` і `.DS_Store` |

`server.py` уже вміє працювати і локально, і на хостингу:

- порт береться зі змінної `PORT`, яку Railway задає сам;
- якщо `PORT` заданий — сервер слухає `0.0.0.0` (інакше Railway не побачить застосунок);
- браузер автоматично відкривається тільки локально.

Перевіряти нічого не треба, це вже працює. Локальний запуск лишається без змін:
подвійний клік по `START_MAP.command`.

## Крок 1. Створити репозиторій на GitHub

Railway розгортає з Git. У терміналі, у папці проєкту:

```bash
cd ~/Workspace/alert-map
git init
git add .
git commit -m "ГОРИЗОНТ — радарна карта тривог"
```

Далі створіть порожній репозиторій на github.com (без README), і виконайте
команди, які GitHub покаже після створення — приблизно такі:

```bash
git remote add origin https://github.com/<ваш-логін>/<назва-репозиторію>.git
git branch -M main
git push -u origin main
```

> Репозиторій можна зробити приватним — Railway однаково матиме до нього доступ
> після підключення GitHub-акаунта.

---

## Крок 2. Створити проєкт на Railway

1. Зайдіть на https://railway.com/ і увійдіть через GitHub.
2. **New Project** → **Deploy from GitHub repo**.
3. Дозвольте Railway доступ до репозиторію, оберіть свій.
4. Railway сам визначить Python і почне збірку. Чекайте, доки в логах
   з'явиться рядок:

```
Карта запущена: http://127.0.0.1:8080/  (слухаю 0.0.0.0:8080)
```

Номер порту буде інший — його призначає Railway.

---

## Крок 3. Увімкнути публічну адресу

За замовчуванням застосунок недоступний ззовні.

1. Відкрийте свій сервіс у проєкті.
2. **Settings** → розділ **Networking** → **Public Networking**.
3. Натисніть **Generate Domain**.
4. Отримаєте адресу виду `https://<щось>.up.railway.app` — це і є ваша карта.

Порт вказувати не потрібно: Railway сам зіставить свій `PORT` із зовнішнім
443/HTTPS.

---

## Крок 4. Перевірити

Відкрийте видану адресу. Має бути:

- карта з янтарною темою і написом **ГОРИЗОНТ** у верхній панелі;
- ліворуч угорі рядок `ТРИВОГИ: РАЙОНИ n/n | ОБЛАСТІ n/n | 1 С ТОМУ`;
- праворуч угорі лічильник `ЦІЛІ: n`.

Якщо замість карти порожній екран — відкрийте консоль браузера (F12) і
подивіться помилки; найчастіша причина в тому, що `neptun.in.ua` тимчасово
недоступний, тоді в рядку стану буде `API ТРИВОГ НЕДОСТУПНИЙ`.

## Про що варто знати заздалегідь

**Навантаження на NEPTUN не залежить від кількості відвідувачів.**
У `server.py` вбудовано кеш відповідей, тож скільки б людей не відкрило карту,
до `neptun.in.ua` йде стала кількість запитів:

| Ендпоінт | Кеш | Запитів до NEPTUN |
|---|---|---|
| `/api/alerts` | 3 с | ~20 за хвилину |
| `/api/threats` | 4 с | ~15 за хвилину |
| межі областей і районів | 1 година | 1 на годину |

Одночасні запити зливаються в один: якщо кеш саме протух і в цю мить прийшло
50 відвідувачів, у мережу піде **один** запит, решта дочекається його результату.
Якщо NEPTUN тимчасово недоступний, до 30 секунд віддаються останні відомі дані,
далі — чесна помилка замість застарілої обстановки під виглядом свіжої.

**Вартість.** Railway працює за моделлю оплати за спожиті ресурси; безкоштовного
безстрокового тарифу немає — після пробного кредиту потрібен платний план.
Застосунок легкий (Python без залежностей), але це не «нуль».

**Своє доменне ім'я.** Там же, у **Settings → Networking**, є **Custom Domain**:
додаєте домен і прописуєте CNAME у свого реєстратора.

**Змінні середовища.** Нічого задавати не потрібно: `PORT` Railway ставить сам.
За бажання можна задати `OPEN_BROWSER=0` — але на сервері браузер і так не
відкривається.
